Token X-ray

A loss function is an equation. A trainer is a program. These are radiographs of the program: the gradient weight every token actually received, measured through unmodified training code.

pip install token-xray Start with the equation

Every token gets a vote

A language model is trained on the average loss over the tokens in a batch. With N target tokens, each one's gradient is scaled by exactly the same amount:

On a radiograph of one training step, where each cell is a token and its brightness is the weight it received, that is an even, featureless grey. Featureless is healthy. Rows are sequences; their length is the number of tokens they contribute.

Splitting the batch should change nothing

Large batches rarely fit in memory, so trainers split them into micro-batches and add up the gradients. Done right, the radiograph cannot tell the difference.

  1. The transformers Trainer, four accumulation steps

    Twelve sequences, four micro-batches of three, through the unmodified Trainer. Every token lands within 10−7 of its intended weight. This is a real run.

  2. Average each micro-batch first, then average the averages

    Micro-batches with few tokens now count as much as micro-batches with many, so their tokens get louder. The bands are the bug. This is the mechanism behind the gradient-accumulation loss bug that transformers fixed in October 2024, reproduced in plain PyTorch.

  3. Keep only the first micro-batch

    Three quarters of the batch goes dark and nothing crashes. This is the mechanism reported for an optimizer-offload path in DeepSpeed, one of the silent bugs that undermined a line of published fine-tuning baselines until a 2026 paper found it.

Some objectives tilt the vote on purpose

Reinforcement learning on language models scores whole answers. Six answers to one prompt, three right and three wrong, and three ways to turn their rewards into token weights. Brightness is how hard each token is pushed; the label says which way.

Small settings rewrite the objective

None of these is a library bug. Each is a configuration that quietly changes which tokens count, and each shows up on the film.

Documents that read each other

Packing several documents into one row saves padding, as long as they cannot see each other. Here, one document at a time is given a loss, and every other document should receive exactly zero gradient. Each film is a grid: the row is the document with the loss, the column is the document that received gradient.

A candidate finding

transformers detects packed documents from position_ids only when no cache object exists. Most model configs default to use_cache=True, which creates one even in training mode. A hand-written loop that feeds packed position_ids without use_cache=False lets documents attend to each other, with no warning. The Trainer is not affected: it sets the flag from its arguments. X-ray your own training step

Write a function that batches the probe's sequences exactly as your trainer does and runs one backward pass. Token X-ray swaps in a tiny model whose every token is a unique tracer and reads back the weight each one received. 

from token_xray import xray

def my_step(model, sequences):
    batch = my_collator(sequences)       # your code
    loss = my_loss(model, batch)         # your code
    loss.backward()

report = xray(my_step, lengths=[5, 9, 3, 12, 7, 4, 10, 6])
report.assert_token_mean()               # fails loudly if any token is off

Every check in the package is tested in both directions: it passes on correct code and fails on the bug it claims to catch. Corrupting the readout, the probe, a closed form or the leak harness makes the suite fail.

How these films were made

Real runs use the unmodified library named on the film. Emulations reproduce the documented mechanism of a historical bug in plain PyTorch and are labelled on the film's edge. Measured with . Weights are shown as w·N, so a correct global token mean is 1.0; the instrument's precision floor is about 10−7.

The probe is a two-layer LLaMA with untied embeddings. In weight mode its attention output is zeroed, so each token's loss depends only on its own embedding and the gradient the stack produces at token i is wi times that token's unit gradient. The readout recovers wi and a cosine that drops below 1 when the change is not a pure rescaling.
